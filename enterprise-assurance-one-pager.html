Prior authorization PoC · Enterprise assurance blueprint · 21 Jul 2026

FROM PLAYGROUND DEMO TO CONTROLLED EVIDENCE SYSTEM

Foundry-native intelligence.
Harness-enforced trust.

Build a provider-side prior-authorization evidence assistant using synthetic data in the existing Azure subscription. It maps policy criteria to source-linked synthetic evidence, surfaces gaps and conflicts, drafts only from verified facts, and leaves submission decisions with an accountable human.

The non-negotiable truth

No generative system can guarantee that it “will not hallucinate.” Enterprise grade means unsupported content cannot silently become an operational action: constrain it, verify it, fail closed, trace it, test it, and require human review.

1 · Target runtime: seven controlled stages

The LLM proposes a bounded evidence map; deterministic services decide whether that map may enter workflow.

01 · INTAKETrusted backendAuthenticated user, synthetic/approved case, supported procedure, file/type/size limits.
02 · POLICYPin exact authorityPolicy ID, version, effective date, source URL, hash, chunk and page locators.
03 · PRE-CHECKReject unsafe inputSchema, malware, prompt/document attacks, case isolation, PHI and secret controls.
04 · FOUNDRYBounded model stepCriterion mapping only; no approve/deny authority and no external side effects.
05 · VERIFYHarness is authoritySchema enums, known criterion IDs, verbatim quote resolution, source linkage, prohibited fields.
06 · HUMANReview and attestResolve gaps/conflicts, confirm draft, choose workflow action, supply override reason.
07 · OBSERVETrace and evaluateRun IDs, spans, versions, latency, token/cost, guardrail outcomes, reviewer feedback.

2 · Four-layer assurance model

Native safety is necessary, but the clinical evidence contract remains a custom responsibility.

Deterministic code gates

Harness
  • Input schema, procedure allowlist, policy/date pinning
  • Known criterion and status enums
  • Exact quote and citation resolution
  • No approve/deny fields or tool actions
  • Retry once; then fail closed

Foundry native controls

Platform
  • Prompt-agent tracing and Application Insights
  • Quality, safety, task-adherence evaluators
  • User/indirect prompt-attack controls
  • Agent guardrails and intervention points*
  • AI red-team scans and attack-success reporting*

Domain evidence controls

Product
  • Policy ↔ clinical dual provenance
  • Supported / not evidenced / conflicting / unable states
  • Code-derived workflow state
  • Missing-information questions
  • Draft only from verified claim IDs

Human governance

Workflow owner
  • No autonomous coverage or medical-necessity decision
  • Explicit submission/review control point
  • Required override reason and attestation
  • Least-privilege access and audit review
  • Rollback, incident, and retention process
!

Current platform caveats matter. Microsoft documents agent guardrails as preview; Groundedness and Spotlighting controls are not currently applicable to Foundry agents. Structured Outputs are not currently supported with Foundry Agents Service. Therefore the current prompt-agent demo needs strict backend post-validation, or the bounded mapping step should move to a Foundry Responses API path that supports Structured Outputs. Preview controls cannot be the sole release gate.
