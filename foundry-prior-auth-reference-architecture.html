The governing architecture rule

Model proposes; deterministic code verifies and derives state; a human decides the next consequential action. Foundry is the managed agent/runtime layer. It is not the policy engine, application authorization layer, audit system, or release authority.

Explicit non-goal

There is no autonomous approve, deny, payer-submission, EHR-write, or external tool path in this PoC. Adding one later would be a new architecture and governance decision—not a configuration toggle.

Fail-closed design

Where common Prior Auth failures stop

Every high-impact failure has a named detection point, code-derived state, and evidence artifact.

Missing required evidence

Domain evaluator/harness derives `more_information_required`; reviewer may request documentation.

Stale or mismatched policy

Policy gate stops before model invocation; no criterion assessment is created.

Unresolved citation or quote

Citation/quote validator blocks the output before reviewer-ready state.

Malformed structured output

Strict parser/schema validator rejects response; raw prose is never treated as workflow data.

Prompt/document injection

Foundry and custom controls record intervention; document text remains untrusted data.

Approve/deny/submit attempt

Action allowlist blocks the request and records a critical assurance event.

Cross-case evidence reference

Case-isolation and source-ID validation reject evidence outside the active synthetic bundle.

Missing trace or unknown version

Release/observability gate blocks promotion because the result cannot be reconstructed.

Real-data upload

Synthetic-scope control rejects processing and routes the event to the privacy/security owner.
